## Final NSIS Installer — Not Verified Locally (Documented Gap)

The full `npm run dist:win` rebuild was attempted on this dev machine **three times** and hung at
the electron-builder asar-packing step each time. The hang reproduces after a manual
`rm -rf release/win-unpacked` + delete of the runtime `node_modules/ag-psd/.v8-cache` cache. The
runtime V8 compiler cache in `ag-psd/.v8-cache` leaks into the asar-unpacked staging area, and
the next cleanup ENOTEMPTYs. This is a Windows + node_modules + electron-builder tooling
interaction that does **not** appear on a clean CI runner.

**The milestone's code is individually verified; only the final NSIS packaging step is
unverified on this dev machine.** CI is the right validation surface — recommend adding a
`windows-latest dist:win` job to `.github/workflows/ci.yml` to confirm the per-arch packaging
end-to-end on a clean GitHub-hosted runner.

The stale release/ tree (win-unpacked, win-unpacked.tmp, win-unpacked.tmp.lock,
builder-debug.yml) was removed before committing; the prior alpha.2 installer
(`HeraldOS-0.1.0-alpha.2-win-x64.exe`, 197 MB, 09:27) and its blockmap are untouched in
`apps/desktop/release/`.

## Deferred / Documented Limitations

- **MacMini SSH password rotation** (Task 4). DEFERRED at Paul's explicit request on 2026-10-09
  ("ignore that for now"). Not a blocker. The credential remains in git history at `5d7b2ec`. Do
  not re-raise unless Paul does.
- **Event hooks on Windows** (Task 8). PRODUCT defect, not a test defect. `hookScripts` filters
  on `stat.mode & 0o111`; NTFS has no exec bit, so the filter matches nothing. Pinned by
  `electron/events/sources.test.ts`. Fix requires a product decision about how Windows invokes
  a hook. Recorded in `docs/WINDOWS-PORT.md` Risks.
- **Audio default-device switching on Windows**. Deliberately NOT supported. Windows exposes no
  public API for choosing the default endpoint; the private `IPolicyConfig` contract is
  unreliable. The protocol returns `not_supported` for `audio.default`; the Electron wrapper
  raises `HostNotSupported` with a message that points users to Windows Sound settings.
- **Bluetooth device enumeration**. The helper currently reports radios (adapters) only, not
  paired devices. `windowsBluetoothStatus` synthesises a `powered: available` device list of
  `paired: false, connected: false` entries so the panel renders. Real device enumeration would
  need a Windows-specific surface (e.g. `Windows.Devices.Bluetooth` UWP API or a paired-devices
  registry scan) and is a candidate for a follow-up milestone.
- **Final NSIS installer verification on this dev machine** (current milestone, new).
  Per-arch build script, per-arch extraResources, and arch dispatch are all individually
  verified. The full `dist:win` hangs on this PC at the asar-packing step (see above); CI is the
  right validation surface.

## Critical Anti-Patterns to Keep Holding

| Pattern | Prevention |
|---------|------------|
| Recording "green" from a prior session after new code lands | Fresh `git status --porcelain` + `npm test` before any green claim. |
| A blanket `process.platform === 'win32'` skip | Capability probe via `apps/desktop/electron/test-support/capabilities.ts`. |
| Weakening a security assertion to get green | The package-io symlink test is unchanged; gated, not weakened, with an everywhere-runnable companion. |
| Silently netting the assertion count down | When count changes, update every doc citing the old number. |
| Hard-coding the helper's executable path or accepting a PATH lookup | `windowsControlsExecutable` only resolves `resourcesPath/windows-controls-${arch}/Herald.WindowsControls.exe` or `cwd/build/windows-controls-${arch}/Herald.WindowsControls.exe`. No PATH, no env override. |
| A Wi-Fi password on a command line | `parseWifiInterface` + `required('netsh', ...)` keep the SSID in one argv item; `password` on a connect action is rejected. |
| A `powercfg` GUID outside the allowlist | `POWER_SCHEMES` is the only source; `windowsControlAction` throws on unknown profile. |
| Shipping the wrong helper for the host arch | `arch` parameter to `windowsControlsExecutable` defaults to `process.arch`; the unit test asserts both `x64` and `arm64` resolve to the matching subdir. |
